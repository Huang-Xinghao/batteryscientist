# 模板中的实验约定

这份说明与代码一起复制到项目。先核对本项目任务，再扩展实现。
模板提供经过检查的默认行为；研究中的新机制放进模型、adapter 或加载器。

## 1. 先明确预测什么、看见什么

- `cell_curves` 输入历史充放电曲线；`soh_sequence` 输入已经测得的历史参考容量。
  两者可观测信息不同，不能直接把结果放进同一张公平比较表。
- `soh_sequence` 的目标为未来 SOH，不是同周期 SOH 估计，也不是寿命预测。
  这里 SOH 为周期内有限放电容量最大值 / 文件中的额定容量。
- 默认滑窗预测每个 origin 都得到新的真实历史容量。这是 rolling-origin，
  不等同于未来真值完全不可见的自主递归预测。递归实验需单独实现并使用独立协议路径。
- 归一化、缺失值填补、阈值与特征统计只能在训练集拟合；验证/测试恢复训练状态。
  模板序列基线直接使用 SOH 比例，没有拟合归一化器。

## 2. 电芯名单先确定，再建窗

准备工具把选定名单写入 `cell_splits.json`，同时保留名单来源和哈希。
默认名单来自随包提供的 BatteryLife 划分，来源文件、commit 与 SHA256 位于
`data_provider/batterylife_splits.json`。它们代表该基准版本的划分，不保证自动适合所有研究。
完整 train/val/test 电芯号可直接查看 `cell_splits.json`。

采用项目自定义名单时，在准备工具传入 `split_file`。准备工具复制快照，后续原文件变化
不会悄悄改变项目名单。文件名重复或跨集合重叠会报错。
SOH 加载器还核对 PKL 内的 cell_id；不同文件别名仍可能需要研究者核对真实物理身份。

不要把同一电芯的不同窗口随机分到训练和测试。不要因为测试表现差重新分组。
`dataaccess` 只减少训练电芯，使用独立的 `split_seed`；训练 `seed` 控制初始化与采样，
不改变电芯成员。同一组多 seed 实验应保留相同划分。

## 3. 一组比较共用一份协议

准备工具配置 `protocol_file=comparison_protocol.json` 的实际项目路径。
第一次加载数据（通常是 check）会保存数据来源、有效窗口数、输入/目标定义和评价口径。
后续同组模型会核对这份内容；变更窗口、划分、源数据或聚合口径会报错。
模型、训练 seed、隐藏维度和学习率可以变化。

因此，第一次 check 前先设好窗口、目标、评价单位。窗口敏感性、另一数据集或另一输入协议
是独立实验，给它们明确不同的 `protocol_file`，例如 `protocols/HUST_L32_H24.json`。
同一模型的候选与正式实验共用协议；不要删除协议文件来掩盖比较条件变化。
手动直接使用源码时，通过 `--protocol_file` 显式启用相同行为。

这项检查核对已记录的数据与设置；它不能自动证明自定义模型没有读取目标，
也不能代替对新增特征、标签和前向调用的检查。

## 4. 实现方法，沿用共同实验路径

- 新模型：增加 `models/` 实现、registry 注册项和 adapter 的 compatible_models。
- 研究损失：覆盖 adapter.loss_parts；它返回损失和与用于归一化的权重。
- 训练采样：在加载器实现；模板提供窗口均匀与电芯均衡采样。
- 预处理：在 adapter.state 保存训练拟合状态，并从 loaders(state) 恢复。
- 指标：用统一的 adapter.metrics；新增统计不能混淆窗口微平均和电芯宏平均。
- 修改共享训练循环时，保留 train/validate/test 的语义，并验证新增机制确实进入 loss、
  梯度和正式 manifest 调用链。复制了文件不代表实现了方法。

## 5. 先验证选型，再恢复最终测试

候选使用 `--stage train`，验证集决定超参数和 checkpoint。
`selection_metric=trajectory.rmse` 以验证集该指标最小值保存权重，
`selection_metric=loss` 使用验证损失；两者不必与训练目标相同。
本模板当前选型方向为越小越好。

所有最终测试恢复已保存 checkpoint 和预处理状态，并核对数据/模型配置。
无参数基线也保存可恢复状态和 fit_status.json，不虚构训练过程。
多候选的最终 test 仍由项目 manifest 依赖表达；模板不能判断 agent 是否已经选完全部候选。
不要用测试指标决定模型、阈值或后续搜索范围。

## 6. 对比和报告

读取 BASELINES.md 选择适用基线，统一历史长度、预测长度、电芯、有效窗口、单位和指标。
有训练参数的模型使用约定的候选范围与训练预算；确定性基线只运行一次即可。
不能通过给基线更少的历史、不同归一化或不合理训练参数制造优势。

SOH 预设使用 cell_macro：每电芯先聚合所有 origin 和预测坐标的误差，计算 RMSE/MAE，
再电芯等权平均。SOH 为比例值；误差乘以100才是百分点。
报告多 seed 时保持每个 seed 的结果，不将不同模型或数据集合并平均。
配对统计按电芯身份对齐；窗口数不是独立电芯样本量。

保留 data_manifest、checkpoint、training_history、validation_metrics、metrics、
预测/真实值 CSV 和 samples JSON。manifest 及执行回执由项目 runner 管理。
负结果保留原比较、消融与证据，按真实效果解释。
