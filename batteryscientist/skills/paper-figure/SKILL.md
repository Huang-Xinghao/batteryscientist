# 论文图表绘制

按当前项目的实验计划和论文计划完成图表：读取真实数据、编写绘图脚本、渲染、自检并交付写作接口。
图的数量、分组、图号和子图由项目计划决定。实验未完成或失败时，保留其缺口或失败状态；不能用不相关图表填补后宣称覆盖。
默认保留计划中的组合图和子图分组。可读性修改优先调整字号、图例、间距、行列和整图尺寸；
本阶段可以从已有产物计算绘图所需的派生统计，不重新设计实验、不启动训练、不补造数据或数字。

## 工具如何配合

- 架构图：用 `write/edit` 编写 TikZ 底稿，用 `bash` 编译 PDF 并导出 PNG；需要真实数据嵌图时，用 Matplotlib 绘制后嵌入底稿。
- 生图润色：调用 `generate_image(prompt=完整编辑文本, image_path="figures/architecture/architecture_tikz.png", output_path="figures/ai_generated/architecture_generated_v1.png", size="auto", quality="high")`，将底图交给图像编辑接口。完整 prompt 和调用说明见[架构图绘制指南](references/架构图绘制.md)。
- 数据融合：用 TikZ 或合成脚本将原始 Matplotlib 图表回嵌到润色后的架构图，保存最终融合版。
- 结果图与表格：用 `write/edit` 编写 Python 绘图脚本或 LaTeX 表格，用 `bash` 运行、编译；数据图导出矢量 PDF 与同版 PNG。
- 视觉检查与修订：用 `view_image(path="实际生成的预览路径", detail="high", max_side=2048)` 查看整图；代码绘图修改源文件后重新渲染，生图编辑以当前候选图作为 `image_path`，新版本另存。

## 输入与职责边界

开始前读取：

1. `PAPER_PLAN.md`：论文主张和叙事顺序。
2. `refine-logs/FINAL_PROPOSAL.md`、实际模型代码/配置：研究任务、输入边界和已实现机制。
3. `experiment-runs/` 执行收据、`experiments/README.md` 中的计划覆盖记录（若有）、`results/` 中的真实 JSON/CSV、逐样本预测和必要的数据缓存。
4. 按图的类型读取指南：
   - 架构图：[架构图绘制指南](references/架构图绘制.md)，通过 `skill_resource_read(name="paper-figure", resource="references/架构图绘制.md")` 读取，用于设计面板、绘制 TikZ 底稿、组织编辑 prompt 和融合真实数据。
   - 数值图：[电池绘图指南](../../../电池资源库/代码和绘图指南/电池绘图指南.md)，通过 `battery_resources(action="read", resource_id="代码和绘图指南/电池绘图指南")` 读取，参考数据集与结果展示、共享样式及真实产物示例。

**计划决定内容，结果决定可画范围，指南提供视觉设计。** 

`PAPER_PLAN.md` 用于组织论文，`EXPERIMENT_PLAN.md` 用于核对证据覆盖。论文计划若已删除或替换实验计划的必做证据，应记录差异，不能把它自动视为实验要求取消。只调整排版时可以改变行列、尺寸和图型，但每个原定必做面板仍须对应已绘制项、明确有依据的替代项或待补项，不能只对照缩减后的论文计划宣称覆盖完整。

## 工作流程

### 第 1 步：阅读图表规划

解析 PAPER_PLAN.md 中的图形计划表：

```markdown
| ID | 类型 | 描述 | 数据来源 | 优先事项 |
|----|------|-------------|-------------|----------|
| 图1 | 架构图 | ... | 最终方案与实际模型实现 | 高 |
| 图2 | 线图 | ... | results/ 中对应运行的 training_history.json | 高 |
```

确认：
- 哪些图表可以根据数据自动生成
- 哪些架构图需要设计 TikZ 底稿并进行生图润色
- 哪些是比较表（生成为 LaTeX ）

### 第 2 步：设置绘图环境

- 用 `battery_resources(action="read", resource_id="代码和绘图指南/paper_plot_style.py")` 读取共享样式，复制到项目 `figures/paper_plot_style.py`。
- 所有主图、补图和训练曲线脚本在绘图前导入这份样式，项目配色等调整集中在其中。
- 默认Arial，中文使用Noto Sans CJK SC；轴标题10 pt，刻度、图例和注记9 pt，常规字重。
- 每个子图的编号和标题默认11 pt加粗，使用 `panel_title(ax, label, text)`；主图、补图和训练曲线保持一致。刻度、图例和注记保持常规字重。
- 子图可见边框默认1.2 pt，双y轴与inset保持一致。
- 按论文最终尺寸检查可读性；指定期刊时统一采用期刊规范。
- 绘制前根据论文计划或实际 LaTeX 模板确定页面、可用图宽与高度，为图注预留空间；在 `figure_plan.md` 记录整图的目标放置尺寸。未指定期刊时采用写作阶段默认模板的版面，不把超高图的适配留给下游。

### 第 3 步：设计架构图

读取并遵循[架构图绘制指南](references/架构图绘制.md)：

```text
skill_resource_read(name="paper-figure", resource="references/架构图绘制.md")
```

根据 `refine-logs/FINAL_PROPOSAL.md` 设计“动机—方案—部署场景”三个面板，按指南完成 TikZ 底稿、编译预览和生图润色。需要融合真实数据时，用 Matplotlib 生成嵌图，并在润色后将原始图表回嵌到最终布局。

在 `figures/figure_plan.md` 记录面板设计、目标尺寸、数据来源和资产路径；保留 TikZ 源码、编辑 prompt、模型原始输出及正式引用版本。

### 第 4 步：设计结果图

根据每张图要回答的问题与实际数据，参考电池绘图指南中的“数据集展示”或“结果展示”选择图型。为计划中的数据图编写可重跑的 Python 脚本，从实验产物读取数据，完成派生统计、面板排版和图例标注；比较表整理为独立 LaTeX 文件。产物读取方式参考指南中的“从真实实验产物绘图”。

按第 1 步的面板映射组织组合图，在目标页面的宽高内安排子图行列、标签换行、图例和间距，为图注预留空间。使用共享样式导出矢量 PDF 与同版至少 300 dpi PNG。

```text
battery_resources(action="read", resource_id="代码和绘图指南/参考其他论文画图指南")
```

### 第 5 步：渲染后自检

先确认生成命令成功，再用 `find` 或 `bash` 列出本次实际生成且非空的预览文件；只把已确认的真实路径传给 `view_image`，不猜页数、文件名或补零规则。生成、LaTeX 编译、PDF 转图片等依赖步骤用 `&&` 串联，避免前一步失败后仍继续。命令失败时先检查退出码及日志摘要，修复并重新生成；不得继续批量查看预期图片。命令成功也不代表旧预览已更新，须确认目标属于本次成功生成的版本。

重新打开每张实际渲染的 PDF/PNG，按最终论文尺寸检查，而非只看脚本：


对于生成的架构图1，默认进行人工检查和修订，不需要你来进行重复修改，对于你写代码生成图使用 `view_image` 实际查看每张最终 PNG（PDF 使用同版 PNG 预览）。它会把图片作为视觉输入送给当前模型；读取脚本、检查像素尺寸或文件存在不等于看过图片。

按“渲染 → `view_image` → 修正 → 重渲染 → 再次 `view_image`”执行，直到最新版本没有已知的可修复布局问题。**每张图最多修订 2 次**，首次生成不计入。

先看全图，小字仍不清时使用 `max_side=4096` 或生成局部预览再调用工具；不能仅凭放大的局部判断整图排版合格。复杂表格需检查其编译后的 PNG 预览，不能将 `.tex` 文本当作视觉检查。

逐图核对字体、子图标题字重、轴标题与刻度字号是否一致，特别检查双y轴、inset和训练曲线网格；这些新增轴也须遵循共享样式。按目标放置尺寸检查整图与图注能否同页、常规文字是否不小于8 pt；太密时在页面高度预算内调整图高、换行或重排行列，不继续缩小字体。架构图生成prompt沿用同一无衬线字体观感和标题/正文两级字重；栅格图不能保证真实字体匹配，检查文字形状与可读性，不宣称其字体嵌入已验证。

在 figure_plan.md 简要记录检查中发现的问题、修复和仍有的限制；不要求额外视觉回执 JSON 或逐图哈希。

## 必须产出

在项目 `figures/` 下维护：

- `figure_plan.md`：图表与子图的计划映射、设计目标、放置尺寸、数据来源与字段、脚本和资产路径、当前版本及检查结果；待补数据对应到具体面板。
- `architecture/`：架构图的可编辑 TikZ `.tex`、编译 PDF 与 PNG 底稿、完整 `image_edit_prompt.txt`，以及用到的嵌图脚本和原始 PDF/PNG 资产。
- `ai_generated/`：按版本保存生图模型原始 PNG 和生成记录，记录输入底图、编辑 prompt 及实际输出路径。
- 架构图正式版本：供论文引用的 PNG，按需提供 PDF；融合真实数据时，另存原始图表回嵌后的最终版本，并在 `figure_plan.md` 标明合成方式及引用路径。
- 结果图：`paper_plot_style.py`、每张数据图的可重跑 Python 脚本、矢量 PDF 和同版至少 300 dpi PNG。
- 表格：独立 LaTeX 文件及编译后的预览。
- `latex_includes.tex`：与计划 ID 和正式文件对应的 LaTeX 引用片段、图注和表注。图注说明整图与各子图的内容，按需解释符号、单位和误差线；表注说明比较内容及必要的单位、缩写和符号，分析与方法细节交给正文展开。
