# 架构图绘制

根据电池、电解液或材料研究方案，绘制由“动机—方案—部署场景”组成的论文架构图。用 TikZ 确定结构和科学逻辑，用 Matplotlib 融合真实数据，再将底图与具体编辑要求交给生图模型，完成科学图标、紧凑布局和视觉润色。

## 一、理解研究内容

只阅读 `refine-logs/FINAL_PROPOSAL.md`，明确研究对象、问题瓶颈、输入、核心机制、输出，以及训练和推理流程。根据其中的内容设计图形，无需读取论文计划、既有架构图或电池资源库。图中表达方案及其设计动机，不把预期作用当作实验结论。

方案中明确的尺寸要求优先；未规定时，以适合论文通栏显示的尺寸组织三个面板，再根据可读性调整比例。需要融合真实数据时，另外读取所用数据产物及必要的字段说明。

在 `figures/figure_plan.md` 中记录本图的目标、放置尺寸、面板内容、短标签、关键公式、连线关系、数据来源和资产路径。

## 二、确定上下三个子图

默认采用三个全宽面板，上下依次排列：

| 面板 | 核心问题 | 视觉内容 |
| --- | --- | --- |
| **(a) Motivation** | 为什么需要这个方案？ | 研究对象、数据形态和具体瓶颈，用对比、分组或简短信息链突出问题 |
| **(b) Proposed method** | 方案如何工作？ | 输入、表示变换、核心机制和输出，以及必要的属性分支或训练支路 |
| **(c) Deployment scenario** | 新样本如何使用？ | 新电芯或配方、可获得的观测、保存的预处理与模型，以及实际输出 |

方法面板占主要面积，可按约 20% / 60% / 20% 开始安排，再根据实际内容调整高度。每个面板围绕一个核心问题，保持从左到右或从上到下的阅读方向。

动机中的预期作用按研究假设表达；部署场景对应实际任务。例如，总寿命预测展示标量寿命读出，轨迹预测展示观测窗口与未来序列。训练损失和参数更新放在方法面板的辅助支路。

## 三、分配绘图内容

| 内容 | 工具 | 接入方式 |
| --- | --- | --- |
| 模块、连线、标签、公式、简单数据图元 | TikZ | 编写 `.tex`，编译矢量 PDF，导出同版 PNG 底图 |
| 真实曲线、柱状图、散点、热图等 | Matplotlib | 导出独立图表，嵌入 TikZ；最终保留原始图表资产 |
| 科学插图、小图标、局部质感与视觉润色 | 生图模型 | 接收底图与编辑 prompt，重新设计模块的视觉形态、局部构图与科学插图；保留科学关系和数据边界 |

简单的特征条、矩阵格、切片、运算节点和电芯轮廓可直接用 TikZ 绘制。复杂插图可以预留区域，明确其概念、归属、尺寸和风格。

## 四、生成 TikZ 底稿

### 规划视觉表达

为每个主要元素确定名称、视觉形式和重要性，为每条连线确定起点、终点、方向与标签。用明确的分支和汇合节点表达计算关系，区分连接点与交叉线。

- **短标签**：模块内使用名称、名词短语或符号，英文通常控制在一行、约 6 个单词。机制解释和实现细节放入图注或正文。
- **视觉图元**：信号用曲线，序列用切片，表示用向量条或矩阵，加权融合用乘法和求和节点；权重标在对应输入线上。
- **关键数学**：保留解释核心设计所需的公式，其余操作使用名称和必要符号。通常突出一条核心公式，确需并列说明的关键关系可就近标注。
- **信息层级**：核心机制展开，常规步骤简写。按最终图宽分配细节和字号，保留清晰的面板编号与简短标题。
- **真实数据嵌入**：可以规划具体区域留空，将真实生成的图嵌入该位置。

### 编写与编译

统一定义字体、配色角色、线宽、圆角和模块样式，使用具名节点、锚点与坐标参数组织布局。通过 LaTeX 引擎编译，并导出 PNG 预览。

采用白色背景、浅色容器、细边框和少量强调色。同一对象或分支保持同色，实线与虚线具有统一含义。标签使用无衬线字体，公式沿用统一数学符号。

底稿阶段完成三个面板的叙事结构、准确连线和主要视觉形式；查看编译后的图片，修正重叠、裁切、误接和过长标签。如果有误直接修改tikz的源码重新编译，不要把问题留到生图模型

## 五、融合真实数据

真实数据的处理路径为：

**读取已有产物 → Matplotlib 绘图 → 嵌入 TikZ → 生图润色 → 原始图表回嵌与核对。**

将输入数据或结果图以简单、美观的形式融合，往往会产生较好的画图质感

### 选择合适的内容

| 面板 | 可融合的真实材料 |
| --- | --- |
| Motivation | 数据覆盖、工况分布、代表性曲线差异、数据输入 |
| Proposed method | 实际输入曲线、输入张量热图、预处理前后对照，以及已有导出的内部响应 |
| Deployment scenario | 保存的示例预测，或真实前缀配合符号输出 |

性能、预测、路由权重和内部特征使用对应版本的真实导出。缺少数值产物时，使用明确标注的概念示意或符号输出。概念曲线与实测曲线在图注中区分。

### 绘制与嵌入

1. 按最终区域尺寸绘制图表，统一字体和颜色角色；项目已有 `figures/paper_plot_style.py` 时可复用。
2. 导出完整的矢量 PDF 和同版 PNG，保留坐标、图例、色条与必要边距。
3. 使用 `\includegraphics` 将 PDF 嵌入 TikZ，等比放置，资产采用相对路径。
4. 在设计记录中为图表分配 ID，记录面板、区域、绘图脚本和资产路径。
5. 查看整体预览，核对图表尺寸、文字可读性与数据含义。

### 生图保护与最终回嵌

生成模型可能重绘曲线、刻度和文字。生图 prompt 应列出真实图表所在区域，要求保留完整矩形槽位和原始纵横比，润色周围模块与图标。

```text
The plot in [panel and location] is rendered from real data with Matplotlib.
Preserve its traces, axes, tick values, labels, legend and color scale.
Keep a clean rectangular slot with the same plot aspect ratio while
polishing the surrounding architecture. The original plot asset will be
placed back into this slot for the final export.
```

最终将原始 Matplotlib 图表完整嵌回润色后的布局。可将生成的局部视觉资产放回 TikZ，也可在最终布局中合成原始图表；等比放置，保持坐标、图例和色条完整。

分别保留**模型原始输出**与**真实数据融合版**，交付时说明是否经过回嵌合成。需要矢量数据部分时，在 TikZ/PDF 中使用原始图表 PDF。仅包含概念示意的图片无需执行数据回嵌。

## 六、生图编辑 prompt 与调用模板

将 TikZ PNG 底图作为图片输入，使用下面的完整 prompt。只需填写 `FIGURE_CONTENT`、`ICON_MAPPING` 和 `REAL_DATA_INSERTS` 三块；内容取自 FINAL_PROPOSAL 和本次底稿。没有真实图表时，`REAL_DATA_INSERTS` 填 `None; all input traces are explicitly schematic.`。

### 可直接使用的编辑 prompt

```text
你正在润色一篇科学研究论文的主图，研究领域为机器学习、人工智能或计算研究。这张图既会出现在论文中，也会用于面向公众的材料，例如项目主页、博客、幻灯片和社交媒体，因此必须同时具备科学严谨性和视觉吸引力。
请生成一个达到顶级会议或期刊出版要求的新版本，例如 NeurIPS、ICLR 或 Nature 级别，并使它具有足够的表现力，能够独立展示。输出必须明显比输入更有吸引力，同时严格保留相同的内容元素集合。
你的职责是在保留核心逻辑和科学严谨性的同时，用简约、高级和吸引人研究的方式画出架构图，尽可能减少过多文本

必须体现的风格变化
- 现代、协调的配色：优化输入图已有的颜色，不要替换它们。在原有颜色基础上形成明确、协调的配色体系，通常采用 3–5 种具有清晰语义角色的色相。调整饱和度和明度，使整体协调；只在原图为单色或默认灰色的区域增加颜色。鼓励使用醒目的强调色和带色填充，避免苍白的灰色和默认样式感过强的平淡配色。强调元素或结果元素使用饱和的纯色填充，不要使用亮面渐变，因为亮面强调色容易产生营销幻灯片的观感。
- 统一字体：使用一种现代无衬线字体，例如 Inter 或 Helvetica Neue。字号保持一致，子图字母使用有辨识度的字重。
- 紧凑、网格对齐的布局：图片在 LaTeX 中会被缩小，因此空白画布会损害标签的可读性。以标签不拥挤为前提，尽可能缩小内容包围范围；将任何大于一行标签高度的空白矩形区域视为需要修复的问题。去除无用留白，让相关元素靠近。框内保留舒适的内边距，避免文字贴边。你可以自由移动、重新分组、重新排布元素和重新布置箭头路径，以消除无用空间；如果能让布局更紧凑，也可以将某个面板从横排改为竖排或网格。元素集合及每条连接的含义必须完全不变，但位置和布线路径可以变化。
- 清晰的箭头：相同语义角色使用统一线宽和一致箭头样式，复用配色强化角色。尽可能保持对称：相同角色的框按行或列对齐，成对流程采用对称布线。每条箭头必须保留准确的箭头数量和所在端点：单向箭头仍然是指向同一目标的单向箭头，双向箭头仍然保持双向。不得增加、删除或反转任何箭头。
- 明确的视觉层级：通过颜色、字重和大小，让读者在两秒内理解主要信息，不依赖额外注释。
- 统一的润色方式：欢迎适度美化，但整张图必须保持一致的视觉处理。对于同一语义角色，阴影或渐变等纵深效果应全部使用或全部不使用。如果给某个角色的一个框添加阴影或渐变，那么该角色的所有框都必须使用相同处理，不能只处理其中一部分。不要在同一张图中混用平面的哑光框和带亮面渐变、阴影的框，这种视觉语言混杂会降低设计感。所有位置都可以使用圆角。

小型科学图标
为 ICON_MAPPING 中列出的已有概念添加小型解释性图标和视觉图元，
将其融入对应模块或紧邻区域，同级模块采用协调一致的表现方式。
使用细轮廓、清晰的类矢量几何形状和克制的哑光明暗。
让图标承担解释细节，短标签保持清楚可读。
不要添加厚重标题横幅

如果输出看起来与输入没有变化，或者缺乏生气，你就失败了。

有表现力意味着清晰、自信，并不意味着繁杂或华丽。如果输出显得拥挤、装饰过度或像营销幻灯片，同样算失败。每个视觉元素都必须有存在的理由。宁可使用一处恰当的强调，也不要让三处强调相互争夺注意力。

开始生成！
```

`FIGURE_CONTENT` 描述当前底图的实际内容，按每个面板的主要路径写简洁清单。例如分别列出信号分支、属性分支和融合关系，不粘贴整篇 proposal。`ICON_MAPPING` 给出有用的具体映射，例如 `input prefix -> stacked signal cards`、`frozen encoder -> document and lock`；

### generate_image 工具调用模板

通过项目的 `generate_image` 工具提交底图与完整 prompt，由工具统一读取模型、服务地址和密钥配置。

先读取已保存的 `image_edit_prompt.txt`，将文件中的完整文本填入 `prompt`。图片路径相对于当前项目，输出另存版本：

```text
generate_image(
    prompt="填写第六节模板后得到的完整编辑 prompt 文本",
    image_path="figures/architecture/architecture_tikz.png",
    output_path="figures/ai_generated/architecture_generated_v1.png",
    size="auto",
    quality="high"
)
```

`image_path` 为当前项目内的底图路径。工具提供该参数时上传图片并调用图像编辑接口；省略时执行文本生图。模型、服务地址和密钥由项目配置统一管理。

调用成功后，使用返回的实际输出路径查看图片。生成结果为新的位图，TikZ 源码继续保留；存在真实图表时，再完成原始图表回嵌并保存融合版。

## 七、检查与交付

查看 TikZ 底稿、模型输出和数据融合后的整图，按论文最终显示尺寸检查：

- **科学内容**：输入、核心机制、条件分支、输出和训练/推理边界与设计依据一致。
- **图形关系**：箭头方向、分支与汇合准确，交叉线含义清楚，公式和符号正确。
- **视觉表达**：三面板层次清晰，小图标风格统一，文字简短可读。
- **紧凑程度**：方法面板突出，模块靠近相关路径，没有大面积闲置横带、空跑连线或过大外边距。
- **真实数据**：原始图表已准确回嵌，样本、单位、坐标、图例和统计含义对应。

保存可编辑 `.tex`、编译 PDF 与 PNG、图表脚本和资产、生图 prompt、模型原始输出及最终融合版；在 `figure_plan.md` 记录数据来源和实际检查结果。需要用于论文时，另保存配套图注和引用片段。PDF 中包含的生成式插图仍为位图，保留原始资产以便后续修改。
