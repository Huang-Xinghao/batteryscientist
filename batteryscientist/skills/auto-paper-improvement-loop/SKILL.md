# 论文改进：独立审稿 → 主控派单 → 修改 → 编译

## 目标与分工

围绕当前论文改善科学表述、论证、写作、图表和排版，默认进行一轮。

- **审稿 Agent**：阅读当前稿件和必要证据，给出问题、依据与可执行建议。
- **主控 Agent**：接收每轮完整报告，判断修改范围，向合适的角色派单，读取修改结果并组织交接。
- **执行角色**：完成本次派单涉及的修改和验证，向主控报告修改内容、产物路径及剩余问题。
- **运行器**：调用独立审稿、保存报告与轮次，收到主控继续指令后编译当前稿件，保存本轮 PDF。

审稿标准见 [paper-review.md](paper-review.md)。审稿人的建议是主控安排工作的依据，结合研究目标和已有证据决定如何落实。

## 输入与配置

项目目录为工作目录，按需读取：

- 当前论文：`paper/main.pdf`、`paper/main.tex`、章节 `.tex` 和 `paper/references.bib`。
- 图表：论文实际引用的图、表、图注及生成脚本。
- 论文计划：`PAPER_PLAN.md`。
- 研究证据：实验结果摘要，以及具体问题涉及的 `results/` 文件。
- 用户研究目标和项目已有写作、绘图约定。

沿用 `ReviewRunner` 和现有 Agent CLI 配置：`BATTERYSCIENTIST_REVIEW_MODEL`、`BATTERYSCIENTIST_REVIEW_REASONING_EFFORT` 及审稿超时。每轮开启独立会话，审阅当前稿件；历史审稿和修改日志供主控使用。

## 每轮怎么工作

### 1. 独立审稿并返回主控

首次开始时，运行器保存 `paper/main_round0_original.pdf`。每轮收集当前源码、PDF 页面预览和必要证据，使用 `paper-review.md` 审稿。

报告保存为 `paper/review_roundN.md`，原文附入 `paper/PAPER_IMPROVEMENT_LOG.md`。运行器随后返回主控，交接本轮报告、修改优先级和当前轮次，等待主控组织修改。

### 2. 主控按问题派单

主控读取报告，按问题的影响和依赖安排工作：

| 修改内容 | 建议角色与阶段 |
| --- | --- |
| 论证、主张、方法解释、正文、引用 | paper_writer，paper_write |
| 结果图、图注、绘图脚本和图形布局 | paper_writer，paper_figure |
| 实验实现、数据处理、指标计算或需要补充的实验 | experiment，experiment_bridge |
| 研究方案或数据来源需要澄清 | idea_generator，对应阶段 |

派单说明本轮要解决的问题、相关文件和预期交付；定向修改使用 `full_stage=false`。同一角色可以合并处理相关问题。有依赖时先处理实验或数据，再更新图表和正文。

需要补实验时，由主控结合用户任务、资源和预期收益决定范围，并沿用既有实验执行工具。暂时无法解决的意见，记录具体原因、影响和后续所需材料。

### 3. 执行角色修改并交回主控

执行角色先核对意见涉及的文件和证据，再落实修改。写作沿用 [paper-write 的语言与段落表达](../paper-write/SKILL.md#语言与段落表达)，图表沿用项目绘图约定。

- 主张与真实结果保持一致；有支持的结论清楚表达，实际限制放在相关解释和讨论中。
- 修改论文的最终研究表述，处置过程写入改进日志。
- 修改结果图时复用生成脚本，查看新图，同步图注和正文引用；优先在已有组合图中调整字号、图例、间距和尺寸。
- 涉及方法、符号或适用范围时，同步检查摘要、正文、附录和结论中的相关表述。
- 引用问题按具体论点检索、核实并补充，沿用论文计划中的引用要求。

交付时向主控说明处理了哪些意见、修改文件、验证结果和剩余问题，并追加本轮修改记录到 `paper/PAPER_IMPROVEMENT_LOG.md`。

### 4. 主控确认交接，继续编译

主控读取关键修改产物，确认本轮问题已处理或已有清楚的剩余说明，再次调用完整 `improvement` 阶段继续。

运行器从保存的轮次恢复，复用现有编译逻辑，保存 `paper/main_roundN.pdf`。编译修复沿用现有机制，结合 PDF 和日志检查引用、图表及分页。

本轮修改编译后完成改进，`paper/main.pdf` 为最终稿。

审稿评估修改前的稿件。最终汇总说明评分对应的版本、主要修改、编译情况和剩余问题。

## 记录与恢复

沿用 `workflow-state.json` 的 `improvement_checkpoint` 保存轮次及审稿、修改、编译、完成步骤。中断后根据当前步骤继续，复用已有审稿报告和修改产物。

`paper/PAPER_IMPROVEMENT_LOG.md` 按轮次记录原始报告、主控安排、实际修改和未解决问题。完成本轮后汇总。需要再次审稿时由主控根据用户要求另行安排。

## 交付文件

```text
paper/
├── main_round0_original.pdf
├── review_round1.md
├── main_round1.pdf
├── main.pdf
└── PAPER_IMPROVEMENT_LOG.md
```
